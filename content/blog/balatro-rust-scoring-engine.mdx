<ArticleLanguage language="en">

Balatro Rust is a command-line scoring engine. It reads round input, works out the hand that was played, applies card effects and joker modifiers, and prints the final score as chips times multiplier.

The part that needs care is deterministic rule composition. A hand can trigger several effects at once, so the engine needs one fixed order of operations.

## Scoring Pipeline

Scoring runs in stages. The engine evaluates the base poker hand first. Played cards then add chips and their own effects, held cards add theirs, and independent joker and edition effects adjust the result last.

Each effect family has a fixed place in that order, which is what makes the system testable.

## Hand Evaluation

The hand detector checks strong hands before weak ones. It also supports variant modifiers: altered straight detection, smeared suits, and shortcut-style rules.

Check order decides which category applies. When a hand matches more than one category, the engine has to pick the highest-priority one, and it has to pick the same one every time.

## Joker Effects

Jokers are grouped by when they apply: scored-card effects, held-card effects, independent effects, and edition effects. The project handles blueprint-like behavior by normalizing copied joker effects before final scoring.

Splitting the effects this way keeps one large scoring problem from turning into a single unreadable function.

## Knowledge Points

- Rust fits deterministic engines well: enums, structs, and pattern matching keep state explicit.
- Structured input such as YAML makes CLI test cases easy to write and replay.
- Rule order matters in a game engine because more than one rule can match the same state.
- Splitting effects by when they fire cuts down on accidental interactions between card effects.
- Floating-point arithmetic is worth avoiding when the output needs exact floor-based scoring.
- Complex game logic is easier to work with when it lives in small modules grouped by responsibility.
- Scoring engines are easier to test when they are built from pure transformations wherever possible.

## Takeaway

The repo turns a rule-heavy game into a staged evaluation system. The engineering lesson is to make timing and priority explicit.

<ArticleLanguage language="zh">

Balatro Rust 是一个命令行计分引擎：读取回合输入，算出打出的牌型，结算卡牌效果和小丑牌修正，最后输出筹码乘以倍数的分数。

麻烦的地方在于规则组合必须确定。一手牌可能同时触发好几层效果，程序得有一套固定的结算顺序。

## 计分流程

计分分阶段进行。先评估基础牌型，打出的牌贡献筹码和自身效果，手牌也能追加效果，最后由独立的小丑牌和版本效果修正结果。

每种效果在流程里都有固定位置，系统因此更容易测试。

## 牌型评估

牌型检测先看强牌，再看弱牌，另外支持几种变体规则：变体顺子检测、花色混合和 Shortcut 规则。

顺序会直接影响结果。一手牌同时够得上多个牌型时，引擎要取优先级最高的那个，而且每次都得取同一个。

## 小丑牌效果

小丑牌按生效时机分组：计分牌效果、手牌效果、独立效果和版本效果。项目对 Blueprint 这类复制行为的处理，是在最终计分之前先把复制出来的小丑牌效果规范化。

按时机分组，一个庞大的计分问题就不会变成一个读不下去的大函数。

## 知识点

- Rust 适合写确定性引擎：枚举、结构体和模式匹配把状态摆在明面上。
- CLI 工具用 YAML 这类结构化输入，测试用例写起来方便，也方便复现。
- 游戏引擎里规则顺序很关键，因为同一条状态可能被多条规则命中。
- 按生效时机拆分效果，可以减少牌与牌之间意外的相互影响。
- 最终分数要精确向下取整时，沿途最好别用浮点数。
- 复杂的游戏逻辑拆成按职责划分的小模块，处理起来会轻松很多。
- 计分引擎尽量建立在纯转换之上，测试才好写。

## 要点

这个仓库把规则繁多的游戏拆成了一套分阶段评估的流程。工程上最值得记的一点是：时机和优先级要明确写出来。
