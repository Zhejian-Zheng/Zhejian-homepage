My CV lives in this repo as a LaTeX project. Sections, projects, education, work experience, and page layout each have their own reusable commands, so a new entry is a few lines of LaTeX rather than a manual layout change.

It is a small repo, but the habit is general: a document that changes often is easier to keep straight when it lives in files and shows up in a diff.

## Document System

The preamble loads packages for page geometry, fonts, color, section titles, tables, list spacing, icons, and links. The custom commands sit on top of those and keep each entry's format in one place.

Consistency is the point. A resume gets scanned, not read, and small differences in spacing or heading size are easy to feel and hard to point at.

## Information Architecture

The content runs through education, experience, projects, technical skills, and achievements. What I want from each entry is what was built, which stack it used, and what came of it. A list of tools on its own says very little.

Contact details and referee information need care once the repo is public. Deleting a line later is more work than leaving it out, so I decide what goes in before committing.

## Knowledge Points

- LaTeX gives precise typography and a document that can be rebuilt from source.
- Custom commands cut down formatting drift between sections.
- Version control keeps a version per application target and still shows what changed.
- A technical CV should tie skills to concrete projects and results.
- Density should help someone scan the page, not squeeze in every detail.
- A public repo should not carry referee or contact details it does not need.
- Treating writing as code invites review, iteration, and reuse.

## Takeaway

With layout, content, and structure kept apart, a change to one does not disturb the other. That is most of what makes the resume maintainable, and it is the same reason I keep code in a repo.

这个简历仓库就是我的 CV，用 LaTeX 写的。章节、项目、教育经历、工作经历和页面布局各有一套可复用的命令，加一条新经历只要写几行，不用手动去调版面。

仓库很小，但这个习惯是通用的：一份经常要改的文档，放进文件里、有 diff 可看，维护起来会清楚很多。

## 文档系统

导言区加载了页面尺寸、字体、颜色、章节标题、表格、列表间距、图标和链接这些宏包。自定义命令建在它们之上，把每条经历的格式收在一处。

一致性是重点。简历是被扫读的，不是被逐字读的。行距或者标题字号差一点，读者未必说得出哪里不对，但会觉得整页不够整齐。

## 信息架构

内容按教育经历、工作经验、项目、技术技能和成果来排。每个条目我想看到的是：做了什么、用了什么技术栈、得到了什么结果。只列一串工具名说明不了什么。

简历公开以后，联系方式和推荐人信息就要当心。事后再删一行，比当初不写进去麻烦，所以提交之前我就先想清楚哪些内容不该进仓库。

## 知识点

- LaTeX 的排版精确，文档可以从源码重新生成。
- 自定义命令减少了各章节之间的格式漂移。
- 版本控制让不同岗位的简历版本各自可追踪，也看得清每次改了什么。
- 技术简历要把技能落到具体项目和结果上。
- 排版密度要方便扫读，而不是把每个细节都塞进去。
- 公开仓库不该带着用不上的推荐人信息和联系方式。
- 把写作当代码来管，评审、迭代和复用都会顺一些。

## 总结

排版、内容和结构分开以后，改一边不会牵动另一边。简历能一直维护下去，靠的就是这一点。这跟我把代码放进仓库是同一个理由。
