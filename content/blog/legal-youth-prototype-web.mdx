Legal Youth is a prototype for making legal information easier to explore. It has a React frontend, a Node and Express backend, search flows, resource pages, interactive tools, and a map for finding legal aid.

The technical work here is mostly product structure. Legal information is broad and sensitive, so I split it into routes and workflows a person can follow.

## Frontend

Routing splits the app into its main screens: search, categories, articles, resources, tools, maps, forum, profile, login, and registration. Material UI gives the components a consistent base, and the motion and layout choices make the interface feel more approachable.

The homepage has a search entry point and topic cards for common legal needs. It also has a lightweight keyword-response assistant covering tenancy, employment, student issues, consumer problems, family topics, and privacy.

## Backend

The Express server handles JSON parsing, CORS, security headers, logging, health checks, demo API routes, and serving the React build in production.

Even as a prototype, the backend skeleton matters. Search APIs, accounts, resource storage, and moderation all have a place to plug in later.

## UX

Legal information is already stressful to navigate, and the interface should not make it worse. That means plain language, a clear path to relevant resources, and no pretending to replace professional advice.

The prototype does that by making categories, search, maps, and tools separate paths instead of burying everything in one long page.

## Notes

- React Router is a good fit when the product is a set of user flows. Each route is one step a person can take.
- Material UI can speed up prototyping while keeping visual consistency.
- Helmet, CORS, Morgan, and JSON body parsing are the practical baseline for an Express API.
- Legal guidance products need careful information architecture because users may arrive with an urgent question they cannot phrase well.
- A keyword assistant was enough for the first prototype. Semantic search or a chatbot can come later.
- Maps and resource directories let people act on what they just read.
- Prototype code should still preserve clear frontend/backend boundaries so it can grow.

## Takeaway

Building this prototype was as much a product exercise as a coding one. The pages were the smaller part. The harder part was designing a system that helps someone with a vague or urgent problem find a next step.

<ArticleLanguage language="zh">

Legal Youth 是一个原型 Web 应用，目的是让法律信息更容易查、也更容易看懂。前端是 React，后端是 Node 和 Express，页面里有搜索流程、资源页、交互工具，还有一张用来看法律援助机构的地图。

这个项目的技术活主要花在结构上。法律信息范围大、又敏感，我把它拆成一条条能走通的路由和流程。

## 前端

React 应用用路由把主要页面分开：搜索、分类、文章、资源、工具、地图、论坛、个人中心、登录和注册。Material UI 提供统一的组件基础，动效和布局让界面没那么生硬。

首页有搜索入口和按常见法律需求分类的主题卡片，还有一个轻量的关键词助手，覆盖租房、就业、学生问题、消费者问题、家庭事务和隐私这些方向。

## 后端

Express 服务器负责 JSON 解析、CORS、安全响应头、日志、健康检查、示例 API 路由，以及生产环境里托管 React 构建产物。

它现在还只是个原型，但这层骨架有用。以后要加搜索 API、账户功能、资源存储、内容审核流程，都有地方放。

## 体验上的考虑

看法律信息这件事本身就容易让人紧张。设计上就得降低门槛：用平实的语言，把人带到相关资源，同时不假装自己能替代专业法律意见。

原型用分类、搜索、地图、工具这几条独立路径来做到这一点，而不是把所有内容堆进一个很长的页面。

## 笔记

- React Router 适合这种按用户流程拆开的界面，每条路由就是其中一步。
- Material UI 能加快原型开发，界面也不容易走样。
- Helmet、CORS、Morgan、JSON body parsing 这些中间件，基本就是一套能用的 Express API 底子。
- 法律引导类产品要把信息架构想清楚，因为用户可能带着很急、又说不清的问题进来。
- 还没有语义搜索和聊天机器人的时候，一个关键词助手就够早期原型用了。
- 地图和资源目录让人看完信息之后知道下一步该去哪。
- 原型也应该保留清晰的前后端边界，后面才好扩展。

## 总结

做这个原型，既是产品练习，也是编码练习。页面只是其中一部分，真正要想的是系统怎么帮用户找到下一步。
