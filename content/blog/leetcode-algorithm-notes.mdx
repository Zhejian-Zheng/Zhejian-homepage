The Leet-Code repo is an algorithm practice notebook. The Python solutions are organized by problem number, and they mix brute-force versions, optimized attempts, and exploratory notes.

Read in order, the code shows the path from a direct approach to a better pattern.

## Patterns in the Repo

Many problems fall into common categories: arrays, strings, hash maps, sorting, two pointers, recursion, dynamic programming, and basic math.

Examples include Two Sum, Longest Substring Without Repeating Characters, Climbing Stairs, Longest Consecutive Sequence, Two Sum II, Contains-like matching problems, and subarray counting.

## Learning Value

Some solutions are intentionally simple. Brute force is often the first version that proves the idea. Later the same problem can be revisited with a hash map, a sliding window, a dynamic programming table, or a sorted scan.

The progression matters: interview-style problems are mostly pattern recognition under constraints.

## Knowledge Points

- A hash map often turns a repeated-lookup problem from quadratic time into linear time.
- A sliding window helps when a substring or subarray has to satisfy a constraint that moves as you scan.
- Two pointers work when the input is sorted, or when you can scan it from both ends.
- Dynamic programming stores the results of overlapping subproblems instead of recomputing them.
- Sorting can simplify a problem, at the cost of O(n log n) time.
- Recursion is expressive, but repeated states usually need memoization.
- Keeping notes next to the code makes mistakes and improvements easier to revisit.

## Takeaway

The repo is a learning record more than a product. Its next step is complexity notes and a short reflection for every solved problem.

这个 LeetCode 仓库就是一本算法练习笔记。Python 解法按题号排列，既有暴力版本，也有优化过的尝试和一些随手记下的探索。

按顺序读下来，能看到一道题从直白思路走到更好模式的过程。

## 仓库中的模式

题目大多集中在几类：数组、字符串、哈希表、排序、双指针、递归、动态规划和基础数学。

比如两数之和、最长无重复字符子串、爬楼梯、最长连续序列、两数之和 II、Contains 这类匹配题，以及子数组计数。

## 学习价值

有些解法是故意写简单的。暴力解通常是第一个能把思路跑通的版本，同一道题过阵子回头再做，可以换哈希表、滑动窗口、DP 表或者排序后扫描。

这种前后差异才是重点。面试题大多是在约束条件下做模式识别。

## 知识点

- 哈希表常把反复查找的问题从平方级降到线性级。
- 子串或子数组的约束随扫描移动时，滑动窗口就派得上用场。
- 输入有序，或者能从两头往中间扫时，双指针很好用。
- 动态规划把重叠子问题的结果存下来，不重复计算。
- 排序能简化问题，代价通常是 O(n log n) 的时间。
- 递归写起来顺，但状态重复时一般要加记忆化。
- 笔记写在代码旁边，回头查错和看改进都方便。

## 总结

这个仓库更像一份学习记录，离成品还有距离。下一步是给每道做过的题补上复杂度注释和一小段复盘。
