Zhejian.github.io is an earlier version of the personal site: small, static, and mostly there to present who I am and what I have built.

Put it next to the current homepage and the difference is mostly structure. The old site was a static page. The current one has separate routes, MDX posts, a contact form, and enough room to explain a project properly.

## What changed

The GitHub Pages approach is good when speed and simplicity matter. It is easy to host and easy to understand.

The Next.js version adds structure. Homepage, about, blog, and contact are separate routes. MDX turns what I learn on projects into articles. The contact page can send a message instead of only showing links.

## Product growth

Many developer portfolios follow this path. The first version tells people who you are. Later versions have to do more: explain the work behind a project, show case studies, publish writing, and give recruiters or collaborators a way to reach you.

Adding technology for its own sake is the easy mistake. The stack should make the communication clearer.

## Notes

- GitHub Pages is excellent for simple static publishing.
- Next.js becomes useful when the portfolio needs routing, metadata, dynamic behavior, and a content system.
- A portfolio can start as one page and end up closer to a personal knowledge base.
- Blog posts make projects easier to understand because they explain the decisions behind the result.
- A contact form saves collaborators and recruiters a step.
- Design changes should not cost speed, readability, or maintainability.
- Migrating old pages is also a chance to rethink the branding and the information architecture.

## Takeaway

This repo is a snapshot of where the site started. The current homepage is the same idea with more structure behind it: a fuller technical portfolio.

Zhejian.github.io 是个人网站更早的版本：小、静态，主要用来放自我介绍和做过的项目。

把它和现在的主页并排看，差别主要在结构。以前是一个静态页面，现在有分开的路由、MDX 文章、联系表单，也能把一个项目讲完整。

## 变化了什么

早期 GitHub Pages 版本的优点是快和简单：部署省事，也不用理解太多。

Next.js 版本补上了结构。首页、About、博客、联系各占一个路由。MDX 把项目里学到的东西变成文章。联系页能直接发消息，不再只是挂几个链接。

## 产品成长

很多开发者的 portfolio 都是这么走过来的。第一版先让人知道你是谁，后面就得把项目讲清楚、放案例和文章，还得让招聘方或合作方知道怎么找你。

为了上技术而上技术是最容易犯的错。技术选型应该让沟通更清楚。

## 笔记

- 如果只是静态发布，GitHub Pages 依然很好用。
- 当 portfolio 需要路由、metadata、动态行为和内容系统时，Next.js 才开始划算。
- Portfolio 可以从一个页面长成个人知识库。
- 博客能把项目里的决策讲清楚，这比只展示结果更有用。
- 有联系表单，合作方和招聘者想联系你就少一步。
- 设计迭代不应该拿速度、可读性和可维护性去换。
- 迁移旧页面的时候，正好重新想一遍个人品牌和信息架构。

## 总结

这个仓库是早期版本留下的快照。现在的主页就是一个更完整的技术作品集，起点还是同一个想法。
